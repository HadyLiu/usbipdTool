# 编译

推荐在 WSL 或 Linux 中使用 Docker **交叉编译工具链镜像**（Rust + MinGW）来生成 Windows 可执行文件。该镜像只提供编译环境，**不会在 Linux 容器里运行 Windows 图形界面**。源码在 `docker run` 时挂载进容器再编译。

构建脚本位于 `script/`（不是仓库根目录），会按自身路径定位仓库根目录，因此可在任意工作目录调用。根目录的 `build.rs` 是 Cargo 构建钩子，用于生成窗口图标、ICO 和 Windows 清单，请勿当成辅助脚本移动。

交叉编译镜像定义在 `docker/Dockerfile`。`script/build-image.sh` 使用仓库根目录作为构建上下文，并以 `-f docker/Dockerfile` 指定该文件；根目录的 `.dockerignore` 会忽略几乎全部文件，以保持上下文很小。镜像标签带有这些文件内容的指纹（`toolchain-<16 位十六进制>`），Dockerfile 或 `.dockerignore` 变更后会使用新标签。

日常 `./script/build.sh` **只运行已有镜像**，不会每次都执行 `docker build`。本机若还没有对应标签，会自动调用一次 `script/build-image.sh`。Dockerfile 有改动时请显式重新执行 `./script/build-image.sh`。

若本机已安装 Docker Buildx 插件，**构建镜像时**会调用 `docker buildx build --load`，一般可避免旧版 `docker build` 的弃用提示。未安装时会回退到 `docker build`，该提示只可能出现在构建镜像的过程中。脚本不会自动安装插件。可选安装方式见 Docker 文档：https://docs.docker.com/go/buildx/

## 命令

```bash
./script/build-image.sh    # 构建或重建编译工具链镜像（Dockerfile 变更时使用）
./script/build.sh          # 运行单元测试并编译，输出 dist/UsbipdTool.exe
./script/build.sh test     # 只跑单元测试（Linux 主机目标，核心层，--no-default-features）
./script/build.sh build    # 只编译 exe
```

查看默认镜像名或指纹：

```bash
./script/build-image.sh --print-image
./script/build-image.sh --print-fingerprint
```

在 Windows PowerShell 中也可以：

```powershell
wsl -e bash -lc "cd /home/hady/workSpaceWsl/usbipdTool && ./script/build.sh"
```

本机已安装 Rust（windows-gnu 或 msvc 工具链）时，也可以直接在仓库根目录执行 `cargo build --release`；日常仍建议用 Docker 脚本，以便与 CI 一致。

## 产物与缓存

成功后会得到 `dist/UsbipdTool.exe`。exe 内嵌图标、`requireAdministrator` 清单和版本信息（当前为 0.1.2）。cargo 依赖缓存在 Docker 卷 `usbipdtool-cargo-registry` 和 `usbipdtool-cargo-git` 中，第二次编译会快很多。

需要让 Cargo / 清单 / 界面版本与某个版本号对齐时，可设置环境变量，例如 `VERSION=0.1.2 ./script/build.sh`。日常本地编译不必设置。
