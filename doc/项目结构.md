# 项目结构

当前版本：**0.1.2**。核心逻辑与图形界面分开：`src/core` 不依赖 GUI，可在 Linux 容器里用 `cargo test --no-default-features` 测试（`./script/build.sh test` 即如此）。

## 目录

```
├── build.rs                 # Cargo 构建钩子（保留在仓库根目录）：由图标源生成 PNG/ICO，并嵌入 Windows 清单与版本
├── Cargo.toml
├── docker/
│   └── Dockerfile           # 交叉编译镜像定义
├── script/
│   ├── build-image.sh       # 构建 Rust+MinGW 交叉编译工具链镜像（Dockerfile 变更时使用）
│   ├── build.sh             # 使用已有镜像测试并交叉编译（不重复构建镜像）
│   └── toolchain-image.sh   # 镜像指纹与构建辅助函数
├── doc/                     # 项目文档
├── dist/                    # 编译产物 UsbipdTool.exe（本地生成，不入库）
├── resources/
│   ├── icon.jpg             # 当前图标源文件（1024×1024 JPEG）
│   ├── i18n/                # 中英文词典
│   ├── app.manifest
│   └── app.rc               # 参考用资源脚本；实际嵌入内容由 build.rs 生成
├── src/
│   ├── main.rs              # 入口：窗口 / 图标 / 提权兜底
│   ├── lib.rs
│   ├── core/                # 纯逻辑：解析、命令、配置、i18n、附加偏好
│   └── gui/                 # eframe/egui 主窗口、设置页、热插拔、主题
├── tests/                   # 核心测试与布局/偏好回归测试
└── .github/workflows/ci.yml
```

## 图标

**权威源文件是 `resources/icon.jpg`。** `build.rs` 会在编译时读取该文件（若以后放了 `resources/icon.png` 则优先使用 PNG），生成窗口/页首用的 PNG 以及写入 exe 的 ICO。不要再把根目录的 `icon.jpg` 或已删除的 `resources/icon.ico` 当作源文件。替换 `resources/icon.jpg`（或增加 `resources/icon.png`）后重新构建即可。

## 本地测试与界面约定

- 完整测试与出包：`./script/build.sh`。
- 核心层测试覆盖配置迁移、附加参数校验、命令映射和解析器。
- 界面相关测试覆盖设备列表按 BUSID 数值倒序、窗口默认尺寸（约 1024×760 物理像素，最小尺寸与默认相同）、空闲与忙碌时表格/日志高度不变（提示在页首、无底栏抢高）、仅窗口缩放改变表格高度、表格列宽（编号列进一步压缩为固定宽度，剩余宽度按权重和状态排版下限分给设备与状态，约 600–670 逻辑像素下不横向滚动，并用绘制边界校验常见已附加文案）、按内容收缩的单行六项工具栏（过窄时横向滚动），以及表头/行内容按绘制字形与按钮背景在固定行高内居中。另有按 PersistedGuid/InstanceId 记忆连接意图的状态机测试，以及只作用于显示的设备过滤规则（持久化、取消不保存、身份不按过滤行号）测试（重启、重插换 BUSID、手动分离/解绑、身份歧义、失败退避），不执行真实的 bind/attach。
- 解绑和分离在界面上直接执行；不要把尚未确认的解绑问题当作已修复行为来依赖。
